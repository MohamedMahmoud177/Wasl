# وصل (WASL) — نظام إدارة مكتب شحن + بوابة عميل (متصل بقاعدة بيانات حقيقية)

الآن التطبيق متصل بـ **Supabase** (قاعدة بيانات Postgres + نظام دخول + حماية بيانات)، مش بيحفظ في متصفحك بس. ده معناه:
- أي موظف من أي جهاز أو مكان يقدر يفتح الرابط ويشتغل بنفس البيانات
- كل عميل له حساب يشوف بيه شحناته هو بس، مش شحنات باقي العملاء
- Supabase **مجاني بالكامل** لمشروع بحجمك (500 ميجا قاعدة بيانات، 50 ألف مستخدم شهريًا) — بدون كارت ائتمان

## الملفات
- `index.html` + `app.js` — تطبيق الموظفين (لوحة تحكم، شحنات، تتبع، بوليصة)
- `customer.html` + `customer.js` — بوابة العميل (تسجيل/دخول + تتبع شحناته هو فقط)
- `config.js` — **الملف الوحيد اللي هتعدّله ببيانات مشروعك** على Supabase
- `schema.sql` — أوامر إنشاء قاعدة البيانات، تُنفَّذ مرة واحدة على Supabase
- `style.css`, `logo.svg` — التصميم والهوية البصرية

## خطوات الإعداد (مرة واحدة، حوالي 10 دقايق)

### 1) أنشئ حساب Supabase مجاني
افتح **https://supabase.com** → Start your project → سجّل بحساب GitHub أو بريدك الإلكتروني (بدون كارت ائتمان).

### 2) أنشئ مشروع جديد
اضغط **New project** → اختار اسم (مثلاً `wasl`) → اختار كلمة سر لقاعدة البيانات واحفظها → اختار المنطقة الأقرب لك → **Create new project**. استنى دقيقة لحد ما يجهز.

### 3) نفّذ ملف السكيما
من القائمة الجانبية: **SQL Editor** → **New query** → افتح ملف `schema.sql` المرفق، انسخ محتواه بالكامل، الصقه، واضغط **Run**.

### 4) فعّل تسجيل الدخول بالبريد
من القائمة الجانبية: **Authentication → Providers** → تأكد إن **Email** مفعّل (مفعّل افتراضيًا عادة).
> لتسريع الاختبار: **Authentication → Settings** وأطفئ "Confirm email" مؤقتًا، عشان الحسابات تشتغل فورًا بدون تأكيد بريد. ممكن ترجّعها تاني لما تكون جاهز للاستخدام الفعلي.

### 5) خد بيانات الاتصال
من **Project Settings → API** هتلاقي:
- **Project URL**
- **anon public key**

افتح `config.js` وحط القيمتين دول مكان `YOUR-PROJECT-REF` و`YOUR-ANON-PUBLIC-KEY`.

### 6) أنشئ أول حساب موظف
1. من داخل التطبيق (`index.html`) مش هتقدر تسجّل حساب موظف مباشرة (بقصد، لأسباب أمنية). بدل كده:
2. من لوحة Supabase: **Authentication → Users → Add user** → حط بريد وكلمة سر (مثلاً `admin@wasl.com`)
3. ارجع لـ **SQL Editor** ونفّذ (بدّل البريد):
   ```sql
   update profiles set role = 'staff', name = 'مدير المكتب'
   where id = (select id from auth.users where email = 'admin@wasl.com');
   ```
4. افتح `index.html` وسجّل دخول بنفس البريد وكلمة السر

### 7) ارفع الملفات على استضافة مجانية
نفس خطوات Netlify Drop أو GitHub Pages اللي اتفقنا عليها قبل كده — ارفع كل الملفات (`index.html`, `customer.html`, `app.js`, `customer.js`, `config.js`, `style.css`, `logo.svg`). رابط `index.html` للموظفين، ورابط `customer.html` تشاركه مع العملاء.

## إزاي العميل يستخدم بوابته
1. يفتح `customer.html`
2. يعمل حساب جديد ببريده ورقم هاتفه (**لازم يكون نفس الرقم اللي هيتسجل بيه كمرسل أو مستلم في الشحنة**)
3. بعد كده، أي شحنة يسجّلها الموظف بنفس رقم الهاتف ده هتظهر تلقائيًا في حسابه — وبس هو اللي يشوفها

## بخصوص طلبك "أنا بس اللي أطلع على الكود وأعدّل عليه"

مهم أكون صريح معاك في النقطة دي: التطبيق ده **frontend** (صفحة ويب)، وأي صفحة ويب — مهما كانت خاصة — أي حد يفتحها في متصفحه يقدر يشوف كودها (زرار "View Source" موجود في كل متصفح). دي حقيقة تقنية مفيش طريقة تلتف حواليها تمامًا في أي موقع ويب عادي، سواء بتاعك أو بتاع شركات كبيرة.

**لكن الخبر الحلو:** اللي فعلاً يهمك حمايته مش الكود (شكل الأزرار وتصميم الجداول) — اللي يهمك هو **بيانات عملائك وشحناتك**. ودي محمية فعليًا دلوقتي بشكل حقيقي عن طريق:
- **RLS (Row Level Security)** في قاعدة البيانات: حتى لو حد قرأ الكود بالكامل ونسخه، مش هيقدر يشوف بيانات شحنة مش بتاعته، لأن الحماية مطبّقة على مستوى قاعدة البيانات نفسها مش على الواجهة
- الـ `anon key` في `config.js` آمن يكون ظاهر فعلاً (Supabase مصمم كده بالضبط) — هو مجرد "مفتاح دخول للباب الأمامي"، والـ RLS هي اللي بتقرر مين يشوف إيه بعد ما يدخل

**خطوات إضافية لو حابب تقلل رؤية الكود لغير المصرح لهم (تحسين مش حماية حقيقية):**
- خلّي الـ repository على GitHub **Private** بدل Public (زي ما عملنا قبل كده)، وشارك الرابط النهائي بس (Netlify) بدون الكود المصدري
- لو محتاج منطق تسعير أو قواعد عمل حساسة تكون فعلاً مخفية تمامًا، الحل الصحيح هو نقلها لـ **Supabase Edge Functions** (كود يشتغل على السيرفر مش في المتصفح) — ده ممكن نعمله كخطوة تالية لو حبيت

## أفكار للتوسعة المستقبلية
- صفحة استعادة كلمة مرور للعملاء (Supabase بتدعمها جاهزة: `resetPasswordForEmail`)
- ربط SMS حقيقي بدل المحاكاة (Twilio أو مزود محلي) من داخل Supabase Edge Function
- تنبيه تلقائي عبر البريد الإلكتروني للعميل عند تغيير حالة شحنته (Supabase Database Webhooks)
